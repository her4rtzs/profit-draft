# Implementation Plan — ProFit First-Build Scaffold

Derived from the APPROVED `design.md` (Revision 4) and the binding `AGENTS.md`. The Revision 4 appendix is binding and overrides any earlier assumption in `design.md` (notably: PayMongo webhook facts, race-safe idempotency, `ALLOWED_HOSTS` fail-fast, mobile CSRF token-echo sequence, byte-exact signature handling).

Acceptance gate for the whole build: `python manage.py check` and `python manage.py test` pass offline (SQLite, no network, no live Supabase/PayMongo) on a Python 3.13 venv. Record real verification output to `.agents/tasks/profit-scaffold/verification.md`.

Binding rules carried from `AGENTS.md` into every item: Django ORM only (the sole raw-SQL exception is `supabase/cron/*.sql`); business logic in services/models, not views/serializers; never log PII or payment details; never commit secrets (env vars only); amounts in integer centavos; timezone `Asia/Manila`, currency PHP; fresh migrations only (never edit an applied migration).

Environment note discovered during exploration: Python 3.13.14 and Node v25.2.1 are present. `npm` via PowerShell is blocked by execution policy — invoke `npm.cmd` for the Tailwind build step, or run it from a shell where scripts are allowed. The Tailwind/npm build is only needed for the deploy bundle and the component-render check, not for `manage.py test`.

- [ ] 7. Create `apps/billing` (Module 2): model stubs, service module, and the concrete PayMongo webhook implementing the four Revision 4 binding fixes.
      `models.py` stubs: `Subscription` (FK `MemberProfile`, `amount_centavos` PositiveIntegerField, `status` PENDING/ACTIVE/EXPIRED, timestamps); `Payment` (FK `Subscription`, `amount_centavos`, `status` PENDING/PAID/FAILED, unique indexed `paymongo_payment_id`, timestamps); `WebhookEvent` (unique `event_id`, `received_at`, `status` PROCESSED/UNKNOWN_PAYMENT/IGNORED — no `signature_valid`, no `DEFERRED`). `services.py`: `create_payment_intent(...)` defined but raising `NotImplementedError` (documented stub); `mark_payment_paid(payment)` / `mark_payment_failed(payment)` implemented as the ONLY writers of paid/failed, guarding illegal/stale transitions (ignore a `failed` arriving after `paid` and vice versa — NIT-4). `webhooks.py`: a CSRF-exempt POST-only `paymongo_webhook` mounted at `/webhooks/paymongo/` implementing:
        - Signature verification in a pure helper `verify_signature(raw_body: bytes, header: str, secret: str, *, mode)` — parse `Paymongo-Signature` as `t=,te=,li=`; compute `hmac.new(secret.encode(), msg=t.encode() + b"." + raw_body, digestmod=hashlib.sha256).hexdigest()`; NEVER `raw_body.decode()` before hashing; compare with `hmac.compare_digest` against `te` in test mode and `li` in live mode; select mode from the event payload `livemode`, defaulting to test offline; secret is `PAYMONGO_WEBHOOK_SECRET` (prefix `whsk_`). On mismatch/malformed/missing header → `400`, write NO `WebhookEvent` row, log only the event id if parseable (never body/payload).
        - Race-safe idempotency EXACTLY as the Revision 4 appendix specifies: `get_or_create(event_id, defaults=UNKNOWN_PAYMENT)` then always `select_for_update().get(pk=...)` re-read inside `transaction.atomic()`; terminal duplicate (`PROCESSED`/`IGNORED`) → `200` no-op; wrap in `try/except IntegrityError` that re-reads under lock by `event_id` and applies the same duplicate check (concurrent-insert path).
        - Event-type map: `payment.paid`/`payment.failed` → look up `Payment` by `paymongo_payment_id`, call the single-writer mutator and set `PROCESSED` if found, else `UNKNOWN_PAYMENT` (reprocessable); any other type → `IGNORED` (terminal). All of lookup+mutation+ledger write share one atomic block.
        - Responses: valid+applied or terminal duplicate → `200`; unknown payment → `200` + `UNKNOWN_PAYMENT`; unrecognized type → `200` + `IGNORED`; bad/missing signature or unparseable body → `400` + no row. Logs record only event id + outcome enum.
      Mount `/webhooks/paymongo/` in `profit/urls.py`. Register the app; generate its initial migration.
      Files: `apps/billing/__init__.py`, `apps/billing/apps.py`, `apps/billing/models.py`, `apps/billing/services.py`, `apps/billing/webhooks.py`, `apps/billing/admin.py`, `apps/billing/migrations/0001_initial.py`, `apps/billing/tests/__init__.py`, `profit/urls.py`

## Known gaps / assumptions (called out, not blocking)

- Real PayMongo payment-intent creation, the full checkout flow, reporting aggregation, Supabase Storage/`django-storages`, member self-service enrollment, and deploy automation are deliberately out of scope (design "Out of scope"). `create_payment_intent` and `monthly_summary` ship as `NotImplementedError` stubs.
- The PayMongo webhook is built and unit-tested against the Revision-4-confirmed documented scheme; no real webhook traffic is accepted in production this pass. If a real sample later reveals a structurally different scheme, `verify_signature` and its fixture are rewritten in the billing pass (documented fallback).
- `can_initiate_payment` is defined and unit-tested but has no live caller this pass; wiring it into the intent-creation endpoint is the first task of the billing pass.
- `npm`/Tailwind build is required only for the deploy bundle and the component-render check; the local PowerShell execution policy blocks the `npm` shim, so use `npm.cmd`. `manage.py test` does not need npm.
- `django-components==0.100` and `django-environ==0.11.2` library-wiring details are verified at implementation time by `manage.py check` (component must actually render); the pins stand.
